# Аудит рисков плана рефакторинга

## 1. Синхронность хранилища (Блокер для Этапа 3)

Проблема: В оригинальном скрипте (строки 62–79) настройки загружаются синхронно через GM_getValue при инициализации. Глобальный объект settings готов к использованию мгновенно.

В Этапе 3 планируется внедрить абстракцию IBridge.storage. Однако файловое хранилище в Tauri (@tauri-apps/plugin-store) — строго асинхронное.

Риск: Если ядро попытается прочитать настройки до того, как Tauri ответит, все флаги (например, settings.translateInterface) будут undefined.

Решение: В Этапе 1 (п. 1.8) функцию bootstrap() нужно спроектировать так, чтобы она приостанавливала запуск MutationObserver и рендеринг UI до полного await bridge.storage.getAll(). Состояние настроек должно стать реактивным синглтоном, который резолвится асинхронно при старте.

## 2. Изоляция Cookies и авторизация Shikimori (Блокер для Этапа 4)

Проблема: В скрипте функция fetchShikimoriListV2 (экспортер) делает запросы к приватному API Shikimori через обычный fetch, полагаясь на то, что браузер автоматически подставит cookies текущей сессии (пользователь залогинен на сайте).

В п. 3.6 сказано, что в Tauri запросы пойдут через Bridge.http (на уровне Rust), чтобы обойти CORS.

Риск: HTTP-клиент Rust (под капотом Tauri) не имеет доступа к cookies WebView по умолчанию. Это два разных процесса. Запрос к Shikimori из Rust уйдет как анонимный, и сервер вернет 401/403, даже если в WebView пользователь залогинен.

Решение:

- либо использовать в Tauri механизм извлечения cookies из WebView перед запросом (выполнение document.cookie через IPC-мост);
- либо перевести синхронизацию Shikimori на OAuth2 / API-токены, чтобы передавать токен в заголовке Authorization, отвязавшись от браузерных сессий.

## 3. Конфликт DOM: React (AniList) vs Vue 3 (Виджеты)

Проблема: В п. 2.1 модалки монтируются в конец document.body. Однако виджеты медиа (рейтинги, плеер, франшиза) инжектятся прямо внутрь контента AniList, например sidebar.prepend(ratesBox). AniList написан на React.

Риск: React агрессивно управляет своим DOM-деревом. При soft-update страницы React может уничтожить DOM-узлы Vue-виджетов. Vue об этом не узнает: возникнут утечки памяти (zombie components), а виджет исчезнет до перезагрузки.

Решение: Менеджер жизненного цикла (п. 2.9) должен не только слушать роутер. В MutationObserver нужно добавить детектор: если контейнер Vue-виджета пропал из DOM, нужно вызвать app.unmount() и пересоздать виджет.

## 4. Рекурсия мутаций (Infinite Loop переводчика)

Проблема: В скрипте работает тяжелый MutationObserver, который ловит изменения DOM и прогоняет их через translateNode. Сейчас скрипт защищается классом .am-notr, чтобы не переводить собственный UI.

Риск: При переходе на Vue 3 фреймворк будет генерировать сотни микро-мутаций при реактивном обновлении интерфейса. Если MutationObserver начнет парсить Vue-компоненты, это вызовет лавину обновлений и может повесить вкладку.

Решение: В Этапе 2 нужно жестко исключить все монтируемые Vue-контейнеры из наблюдения. MutationObserver должен игнорировать любые узлы внутри корней Vue-приложений.

## 5. Медиа-кодеки в Tauri (WebView OS)

Проблема: Интеграция плеера Kodik (п. 4.8).

Риск: Браузеры поставляются с проприетарными кодеками H.264/AAC. Tauri использует системные WebView. На Linux WebKitGTK часто не имеет установленных GStreamer-пакетов для H.264/MP4, из-за чего iframe Kodik может показывать черный экран или ошибку.

Решение: В документации/манифесте Linux-инсталлятора необходимо указать зависимости для медиа-кодеков либо добавить программный fallback.

## 6. Управление памятью логгера (SessionStorage)

Проблема: Логгер пишет записи в массив и сбрасывает последние 200 в sessionStorage. В desktop-приложении Tauri нет обычного жизненного цикла вкладки — приложение может работать сутками.

Риск: Массив scriptLogs продолжит расти. LOG_LIMIT = 1000 на каждый тип означает до 6000 объектов в памяти.

Решение: В desktop-версии через TauriBridge логи следует писать потоково в локальный .log-файл через plugin-fs, а в оперативной памяти для Vue-интерфейса держать только кольцевой буфер последних 300–500 записей.
