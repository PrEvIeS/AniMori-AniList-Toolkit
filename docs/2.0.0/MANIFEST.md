Манифест проекта AniMori 2.0

AniMori — это масштабный набор инструментов (Toolkit), делающий платформу
AniList комфортной для русскоязычного комьюнити. Скрипт вырос из простых
улучшений в мощный комбайн с интеграцией внешних баз, плееров и сканеров. Чтобы
проект мог развиваться дальше без боли и ограничений, нам нужна новая
архитектура.

🎯 Зачем это нужно? (Проблематика)

1. Технический долг: Поддерживать и развивать монолитный файл на 3000 строк с
   ручным управлением DOM-деревом (HTML-строки) стало невозможно. Это замедляет
   разработку и повышает риск ошибок (XSS).
2. Браузерные оковы: Жесткая привязка к API расширений (Tampermonkey/GM_)
   делает проект уязвимым к изменениям политик браузеров (например, Manifest
   V3).
3. Сетевые ограничения: Браузерный CORS и региональные блокировки (РКН) мешают
   стабильной работе со сторонними видео-балансерами (Kodik) и API (Shikimori,
   Anime365).

Наша цель — создать независимое, отказоустойчивое и кроссплатформенное
приложение, сохранив при этом единую кодовую базу как для старого доброго
юзерскрипта, так и для нового десктопного клиента.

🛠 Как мы это сделаем? (Стратегия)

Переход будет выполнен в 4 последовательных этапа, без остановки разработки и
без вреда для текущих пользователей:

- Шаг 1: Разделяй и властвуй (Vite + TypeScript). Мы разрежем монолит на
  типизированные ES-модули. Вся логика, кэш и сеть будут строго
  инкапсулированы. Сборку берет на себя Vite.
- Шаг 2: Современный UI (Vue 3). Мы навсегда откажемся от ручной генерации
  HTML. Весь интерфейс (настройки, сканер, логгер) будет переписан на
  реактивные компоненты Vue, которые монтируются в изолированные контейнеры,
  не ломая сам AniList.
- Шаг 3: Независимость от среды (Паттерн Bridge). Мы внедрим слой абстракции
  (Адаптер), который скроет под собой специфичные API. Ядро больше не будет
  знать, где оно запущено — в браузере (GM_) или в ОС (Tauri).
- Шаг 4: Десктопная эволюция (Tauri + Rust). Мы обернем готовый веб-бандл в
  легковесный исполняемый файл Tauri. Он будет невидимо инжектить код на
  страницу AniList, а сетевые запросы будут обрабатываться на уровне ОС (через
  Rust), играючи обходя любые CORS-ограничения и блокировки расширений.

Главный принцип AniMori 2.0: Пишем код один раз — собираем везде. Будь то
юзерскрипт в браузере или приложение на Windows/macOS/Linux, пользователь
получает идентичный функционал, а разработчик — идеальный Developer Experience
(DX).
