# Этап 1: Модуляризация монолита и миграция на сборщик (Userscript)

Цель: Разделение монолитного скрипта на изолированные ES-модули, внедрение
строгой типизации, переход на современный процесс сборки. Стек: Vite,
vite-plugin-monkey, TypeScript, SCSS.

## 1.1. Инициализация проекта и конфигурация метаданных

- Действие: Создание проекта на базе шаблона vite-plugin-monkey (vanilla-ts).
- Миграция метаданных: Блок метаданных Userscript (строки 1–20) переносится в
  конфигурационный файл vite.config.ts.
- Результат: Автоматическая генерация заголовков (@match, @grant, @connect) на
  этапе сборки (build time), устранение необходимости ручного управления
  версионированием внутри JS-файла.

## 1.2. Выделение стилей (CSS/SCSS)

- Действие: Перенос инлайнового CSS (строки 2803–2990, блок GM_addStyle) в
  отдельный файл src/style.scss.
- Интеграция: Подключение стилей через импорт (import './style.scss') в точке
  входа. Сборщик автоматически обработает SCSS, минифицирует его и инжектирует
  в итоговый бандл.

## 1.3. Ядро (Core) и Утилиты (Utils)

- Константы (src/core/constants.ts): Вынос глобальных флагов (IS_SHIKI,
  IS_ANILIST), конфигурации доменов (SHIKI_DOMAINS, ANIME365_DOMAINS) и
  словарей времени (строки 27–60).
- Настройки (src/core/settings.ts): Перенос объекта settings (строки 62–79).
  Реализация типизированных оберток для работы с хранилищем (read/write).
- Утилиты (src/utils/dom.ts): Вынос хелперов для работы с DOM и строками
  (escapeHTML, html, rawHTML, applyMarquee, amCopy).

## 1.4. Слой данных (IndexedDB)

- Действие: Вынос логики инициализации БД, миграций, операций чтения/записи и
  Garbage Collector (строки 969–1165) в файл src/core/db.ts.
- Инкапсуляция: Глобальная переменная globalDbInstance переносится в область
  видимости модуля db.ts без экспорта наружу.
- Типизация: Преобразование JSDoc-описаний (ShikiCacheRecord, MalCacheRecord)
  в TypeScript-интерфейсы для обеспечения type safety при работе с хранилищем.

## 1.5. Система логирования

- Действие: Вынос функции Logger, массива scriptLogs, и утилит safeCall /
  isOwnScriptSource (строки 229–548) в модуль src/utils/logger.ts.
- Обработка ошибок: Регистрация глобальных обработчиков
  window.addEventListener('error' / 'unhandledrejection') инициализируется
  внутри этого же модуля. (Примечание: UI логгера временно остается в модуле
  до миграции на Vue).

## 1.6. Сетевой слой (API) и управление Rate-лимитами

- Действие: Разделение функций запросов (строки 1256–1540) по доменным файлам
  в директории src/api/:
  - anilist.ts (anilistQuery, getAlToken)
  - shikimori.ts (fetchShiki, fetchShikiPersonREST)
  - anime365.ts (fetchAnime365ByMal)
  - animethemes.moe.ts (fetchMalThemes)
- Инкапсуляция состояния: Глобальные счетчики задержек и ошибок
  (alRateLimitPause, shikiRateLimitPause, anime365FailStreak) инкапсулируются
  внутри соответствующих модулей API. Внешний доступ к ним блокируется.

## 1.7. Разделение бизнес-логики (Features)

- Действие: Декомпозиция оставшихся логических блоков в директорию
  src/features/:
  - translator/: Логика MutationObserver, локального словаря и
    translateAdvanced.
  - scanner/: Логика сравнения списков (сканер дельты) и cmpDeepCheck.
  - exporter/: Логика миграции списков Shikimori -> AniList.
  - media/: Инъекция виджетов (Kodik, франшиза, рейтинги).
  - search/: Русский поиск и захват выделенного текста для словаря.

## 1.8. Точка входа (Entry Point)

- Действие: Создание файла src/main.ts с асинхронной функцией bootstrap().
- Логика: Функция последовательно инициализирует модули (openDB, импорты
  стилей), после чего выполняет маршрутизацию логики на основе флагов среды
  (IS_SHIKI / IS_ANILIST), повторяя логику оригинальной функции init()
  (строки 2800+).

Итог Этапа 1: Идентичный по функционалу юзерскрипт с нулевой регрессией. Кодовая
база разделена на типизированные ES-модули, готовые к внедрению UI-фреймворка.
