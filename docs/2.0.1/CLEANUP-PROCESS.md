# Чистка комментариев: порядок работы

Правила и процедуры задачи. Ход работ и результаты — в
`docs/2.0.1/CLEANUP-COMMENTS.md`.

## Зачем

Комментарии занимают около 40% веса исходников. Тяжёлые файлы труднее
править целиком, а пересказ кода словами устаревает раньше самого кода.

Правило — `docs/CODE-STYLE.md`. Чистка НЕ трогает код, только комментарии.
`README.md` и бейджи не трогаем. Ценное «почему» переезжает в `docs/`, а не
удаляется.

### Редакция правила

После чистки `lib.rs` правило ужесточено (`dc20194`): док-комментарий — 2 строки
вместо 3, запрет комментариев из двух абзацев, пустая строка `//` внутри
комментария запрещена. Повод — `NET_PROBE_SCRIPT`, вышедший на 11 строк через
четыре формально коротких абзаца.

Файлы, почищенные до `dc20194`, второй раз не перебираем: они попадут под новые
лимиты при ближайшей содержательной правке.

Про SCSS в правиле пока ничего нет — что дописать, видно из партии 7.

В `.vue` под лимит шапки попадает и HTML-комментарий перед `<template>`.
Разделители секций в `<script setup>` и подписи блоков разметки остаются:
в файле на 500 строк разметки они единственный способ навигации.

## Порядок итерации

Работа идёт партиями по 2–5 файлов, а не пофайльно.

1. Замерить вес файлов партии заново: оценки из очереди устаревают.
2. Прикинуть долю комментариев, а не только вес: см. урок партии 7.
3. Почистить, ценное «почему» вынести в `docs/`.
4. Записать и перечитать файл целиком — после каждого файла.
5. Дописать партию в журнал и перечитать его.
6. Прогнать локальные проверки одним набором на всю партию (ниже).

### Частота проверок

| Действие               | Частота                      | Где выполняется |
| ---------------------- | ---------------------------- | --------------- |
| Перечитка после записи | каждый файл                  | через API       |
| Дифф-фильтр            | раз в партию, списком файлов | локально        |
| `prettier --check`     | раз в партию, списком файлов | локально        |
| `typecheck` и `build`  | раз в партию                 | локально        |
| Запись в журнал        | раз в партию                 | через API       |

Перечитка остаётся пофайловой: она ничего не стоит человеку и уже трижды
поймала брак записи в одной партии. `prettier --write` вслепую по `.md`
отменён: в партии 7 файл из API прошёл `--check` без правок.

### Проверка после итерации (PowerShell)

Рабочая машина — Windows, `grep` нет. Консоль по умолчанию не в UTF-8, кириллица
в выводе `git diff` превращается в мусор. Один раз за сессию:

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8
$OutputEncoding = [Text.Encoding]::UTF8
chcp 65001 > $null
git config core.quotepath false
```

Далее сам набор:

```powershell
git pull --ff-only origin "script&windows-dev"
git diff <до>..<после> -- <файл> |
  Select-String -Pattern '^[+-]' |
  Where-Object { $_ -notmatch '^[+-]\s*(//|/\*|\*)' -and $_ -notmatch '^(\+\+\+|---)' }
npx prettier --check <файл>
npm run typecheck
npm run build
```

Кавычки вокруг имени ветки обязательны: `&` уводит команду в фон.

Фильтр диффа ловит только строки, начинающиеся с маркера комментария. Хвостовые
комментарии вида `const x = 1 // пояснение` он покажет как правку кода — такие
смотрим глазами. В `.vue` он же покажет HTML-комментарии `<!-- -->`, причём
целиком: вторая и последующие строки блока `<!-- -->` начинаются с обычного
текста, и отсечь их по маркеру нельзя. Многострочная шапка `.vue` в выводе
фильтра — норма, а не правка кода.

Для SCSS фильтр шумит, поэтому там сверяем число открывающих скобок до и после:

```powershell
(Select-String -Path "src/style.scss" -Pattern '\{' -AllMatches).Matches.Count
```

Сейчас скобок 309. Сборка в режиме `userscript` строку `dist/animori.css` не
печатает — стили инлайнятся в бандл; отдельный вес CSS (46,76 КБ) виден только
в десктопной сборке.

## Запись через API: что выяснилось

Порог касается текста, который отправляется, а не того, что лежит в репозитории.
Почищенный файл легче исходного, поэтому чистка тяжёлого файла через API
безопаснее, чем кажется.

Оценка порога в 25 КБ была заниженной: `translator/index.ts` записан целиком
одним вызовом на 34 677 б, перечитка подтвердила целостность. Но на партии 9
обрыв повторился дважды подряд на `SETTINGS-UI.md` (26 КБ и 22 КБ), причём оба
раза API вернул успех.

Рабочее правило:

- Код в одну запись — до ~35 КБ (проверено на `translator/index.ts`).
- Сплошной русский текст — до ~18 КБ. Выше этого документ дробим на файлы,
  а не пишем одним вызовом.
- Перечитка после каждой записи обязательна: обрыв отдаёт как успех.

Партия 8 дала второй довод за перечитку, уже не про обрывы: трижды подряд в
текст попадал мусор генерации — оборванное слово в `SETTINGS-UI.md` (`35eaf91`),
посторонний иероглиф внутри комментария `SettingsProxyCard.vue` (`f70d026`)
и семь чужих букв вместо «ё» в журнале. Все три дефекта прошли бы `typecheck`
и сборку незамеченными: это текст внутри комментария или документа. Ловит их
только чтение глазами после записи.

Правки на несколько строк в тяжёлом файле через API не гоняем: партия 7 — восемь
строк в файле на 46 КБ, дешевле и безопаснее поправить локально. Исключение —
`LoggerModal.vue` в партии 8: две правки в 16 КБ отправлены целиком ради того,
чтобы не дёргать человека среди партии.

Файл, созданный через API, проходит `prettier --check` не всегда. Код и
`SETTINGS-UI.md` проходят, а журнал ругается почти всегда — виноваты таблицы:
выравнивание столбцов руками почти никогда не совпадает с тем, что хочет
Prettier. Вывод: `--write` по журналу после каждой записи в него, `--check` по
остальному. `npm run format` бьёт по корневым `*.md` и уже ломал `README.md`
(`b2df266`, откачено `a8f1451`).

Записи в одну ветку идут только последовательно: четыре параллельные дали 409.
