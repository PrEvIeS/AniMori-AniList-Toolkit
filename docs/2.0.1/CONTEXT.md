# Контекст текущего шага

Шаг: пункт 5.3.8 закрыт целиком (`73299fa`…`b02d70e`). Следующий — 5.3.9.

Зачем был нужен: окно и наши запросы — два независимых канала. Запросы
шли с логином, а окно на прокси с авторизацией получало 407 и пустую
страницу. Щуп 5.3.4 этого не ловит: голый TCP-connect видит `Applied`.

Rust. В `proxy.rs` — ключ `set_proxy_pass`, `WindowAuth`, `ProxyCredentials` и
поле `auth` в состоянии. Пароль читается без `trim`: пробел по краям
законен, а тихая правка дала бы отказ.

`proxy_auth.rs` — обработчик `BasicAuthenticationRequested` через
`ICoreWebView2_10`, подключён в `lib.rs` после `build()`. Старый рантайм
или не Windows — запись в журнал, а не падение.

Защита пароля: на адресах `bypass` учётные данные не подставляются,
потолок попыток — пять (Chromium кеширует и переспрашивает), счётчик
сбрасывается по готовности страницы. В журнал идёт только адрес,
логин и пароль — никогда.

Сторож (`proxy_guard.rs`) вместо глухого ожидания 12 с опрашивает шагами
и знает три исхода: `Ready`, `Rejected`, `Silent`. Спросил и замолчал —
один тихий перезаход, второго не будет.

Фронтенд. Исход едет полем `auth` в существующей команде состояния, новой
команды нет. `accepted` косвенный: кода ошибки в событии нет, принятие
видно лишь по отсутствию повторного запроса. В юзерскрипте честное `none`.
Карточка различает отказ, ожидание и успех; ложная подсказка про
«отдельное окошко» убрана, добавлены строка про хранение пароля и
предупреждение про SOCKS5 с логином: такую авторизацию движок окна
не умеет вовсе.

Проверено: `cargo check`, `typecheck` и обе сборки чисты. Живой проверки
не было — нужен прокси с авторизацией, это за владельцем.

Дальше: 5.3.9 — перенос карточки прокси из «Разработчика» в «Прочее»,
затем 5.4 — правка и добавление доменов.
