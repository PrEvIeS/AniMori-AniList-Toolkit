# Контекст текущего шага

Шаг: пункт 5.3.8, авторизация окна у прокси. Rust готов, идёт фронтенд.

Зачем: окно и наши запросы — два независимых канала. Запросы шли с
логином, а окно на прокси с авторизацией получало 407 и пустую страницу.
Щуп 5.3.4 этого не ловит: он делает голый TCP-connect и видит Applied.

Шаг 1 (`73299fa`) — `proxy.rs`: ключ `set_proxy_pass`, `WindowAuth`,
`ProxyCredentials`, `remember_credentials()`, `window_auth()`. Пароль читается
без `trim`: пробел по краям законен и тихая правка дала бы отказ.

Шаг 2 (`da04b41`, `73d3165`) — новый `proxy_auth.rs`: обработчик
`BasicAuthenticationRequested` через `ICoreWebView2_10`, подключён в `lib.rs`
сразу после `build()`. Старый рантайм WebView2 — запись в журнал, не падение.

Защита пароля: на адресах `bypass` учётные данные не подставляются — там
трафик идёт мимо прокси и спрашивать может сам сайт. Потолок попыток — пять
(Chromium кеширует и переспрашивает), счётчик сбрасывается по готовности
страницы. В журнал идёт только адрес, логин и пароль — никогда.

Шаг 3 (`c8175a9`) — сторож подружён с авторизацией. Вместо глухого ожидания
12 с — опрос шагами с ранним выходом и три исхода: `Ready`, `Rejected`,
`Silent`. Если прокси спросил и замолчал — один тихий перезаход без диалога;
второго не будет, его держит флаг. Текст диалога зависит от исхода.

После шага 3 пришлось отдельно чистить комментарии в обоих файлах
(`6e07888`, `d8d8ad9`): лимиты `CODE-STYLE.md` были нарушены при написании.
Сверяемся с ними ДО записи, а не после напоминания.

Шаг 4, запись 1 (`2a1b6b2`, починка `a6db127`) — исход авторизации едет полем
`auth` в существующей команде состояния: новой команды нет, правило трёх мест
не срабатывает. Поле собирается в момент вызова: снимок запуска об авторизации
знать не может, она случается позже. `Accepted` косвенный: кода ошибки
в событии нет, принятие видно лишь по отсутствию повторного запроса.

Осталось по шагу 4: `IBridge.ts`, `MonkeyBridge.ts` (в браузере честное `none`),
`TauriProxyDiagnostics.ts` при необходимости и `SettingsProxyCard.vue`. В карточке
ждёт ложная подсказка про «отдельное окошко», нужны строка про уникальный
пароль и предупреждение про SOCKS5 с логином: такой прокси базовую
авторизацию не спрашивает вовсе. Потом `typecheck` и обе сборки.

Живая проверка возможна только у владельца и требует прокси с авторизацией.
Правило работы прежнее: один файл за раз и обязательное перечитывание после
записи — именно оно поймало сломанный хвост `proxy.rs` в шаге 4.
