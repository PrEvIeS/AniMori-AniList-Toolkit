# AniMori 2.0.1 — работы по сети: план итераций

Ветка: `script&windows-dev`. Заведён 4 августа 2026.

Обоснование и замеры — в `STAGE-5.md`, раздел «Р1. Блокировки сервисов в
России». Здесь только состав работ и принятые решения по интерфейсу.

Главное правило всего нижеследующего: **в коде нет решений, зависящих от
того, что доступно сегодня.** Ни один хост не помечен заблокированным,
страна пользователя не определяется, выводы делаются только по факту отказа
в момент работы.

## Итерация 5.1 — ядро состояния сети и вкладка Разработчик

### Классификация исходов

Новый модуль ядра `core/net-health.ts`. Не содержит ни одного имени хоста:
источники сообщают о себе сами. Хранит по каждому источнику последнее
состояние, время и число подряд идущих неудач.

| Что вернула сеть | Состояние | Совет про VPN |
| --- | --- | --- |
| исключение моста `network` / `timeout` | недоступен | да |
| 403, 451 | не пускает | нет |
| 5xx | сломан на своей стороне | нет |
| 2xx, 404 и прочее | связь есть | — |

Исключены из учёта три случая:

1. `abort` — наша собственная отмена при уходе со страницы.
2. 401 от AniList — истёкший токен, у него уже есть свой текст
   (`TOKEN_REJECTED_MESSAGE`); путать его с блокировкой нельзя.
3. 429 — лимит темпа, им занимается `api/rate-limit.ts`.

Порог — две неудачи подряд по одному источнику. Любой успех сбрасывает
счётчик. Одна случайная ошибка предупреждение не поднимает.

### Отчёты из клиентов

Каждый файл `src/api/*.ts` после запроса сообщает исход по своему
источнику. Прикладная логика клиентов не меняется: те же возвраты, те же
записи в журнал, тот же кэш. Добавляется только отчёт.

### Вкладка Разработчик

Решение владельца (4 августа): проверка сети ставится рядом с логгером,
для обоих заводится новая вкладка Разработчик.

- Тумблер логгера переезжает из Прочего в Разработчик.
- Тумблер адблока остаётся в Прочем (решение этапа 2.9 не отменяется).
- Позже туда же встанет правка доменов (итерация 5.4).
- Тумблера отключения предупреждений не будет: они и так появляются
  только при реальном отказе (решение владельца).

### Проверка сети

Кнопка опрашивает все источники по очереди тем же способом, каким их
дёргает рабочий код (AniList — POST с минимальным телом). Иначе проверка
врёт: первый ручной замер 4 августа дал 404 на живом AniList именно по этой
причине.

- Строки: AniList API, картинки AniList, каждое зеркало Shikimori отдельно,
  каждый домен anime365 отдельно, AnimeThemes API, видео AnimeThemes,
  Kodik API, плеер Kodik, словарь, проверка обновлений, файл обновления.
- В строке: состояние, время ответа, короткая причина.
- Предел ожидания на источник — 8 с: иначе прогон растянется на минуту на
  мёртвых доменах (в замерах таймаут был 10.7 с).
- Повторный прогон не чаще раза в 30 с, иначе кнопкой можно выбить лимит
  AniList. Каждый запрос берёт слот у ограничителя, как и любой другой.
- Итог прогона пишется в `net-health`: проверка обновляет состояния, а не
  живёт отдельно.
- Перечень строк — это список наших источников (факт кодовой базы), а не
  список заблокированного.

## Итерация 5.2 — тост, строки отказа, выбор рабочего домена

### Как видит пользователь

1. **Строка в виджете.** Сейчас виджет при отказе остаётся скрытым и
   человек не видит ничего. Станет так: скрыт — только когда данных
   действительно нет; при отказе — одна строка с причиной и ссылкой на
   проверку сети.
2. **Тост поверх всего.** Решение владельца: именно тост сверху экрана, а
   не плашка в потоке — содержимое сайта не сдвигается. Сам не гаснет
   (иначе человек отвернётся и пропустит), закрывается крестиком,
   больше за сеанс не появляется. Слой и порядок наложения — по образцу
   оверлея плеера, чтобы не оказаться под шапкой сайта.
3. **Когда тост.** Отказ одного источника — дело виджета. Два и больше
   разных источников в состоянии «недоступен» за окно порядка минуты —
   уже про сеть в целом, показывается тост.
4. **Текст зависит от исхода.** Недоступен — совет про VPN. Не пускает —
   сервис отклонил запрос, дело не в сети, совета нет. Сломан — временно
   недоступен, совета нет.

### Резервные домены

- Из констант не удаляется ничего: ни `shikimori.rip`, ни `anime365.ru`.
  Владелец проверил: `anime365.ru` жив, просто отвечает не с первой попытки
  (`ERR_TIMED_OUT`, затем редирект на `/users/login`).
- Ответивший домен запоминается на сеанс и опрашивается первым;
  неудачный уходит в конец очереди.
- Предел ожидания на попытку к резерву — короткий (порядка 5 с,
  `MIRROR_TIMEOUT_MS`). Проверить, что он реально применяется во всех
  клиентах с зеркалами: в замерах одна попытка стоила 10.7 с.

## Итерация 5.4 — правка и добавление доменов

Запрос владельца: дать возможность менять и добавлять домены всех
источников на случай, если они начнут отваливаться.

### Ограничение скриптовой сборки (важно)

Шапка юзерскрипта разрешает сетевые запросы только на восемь адресов
(`connect` в `vite.config.ts`): `raw.githubusercontent.com`, `shikimori.io`,
`shikimori.rip`, `smotret-anime.online`, `anime365.ru`, `graphql.anilist.co`,
`kodik-api.com`, `api.animethemes.moe`. Адрес, которого там нет, Tampermonkey не
пустит, сколько бы пользователь ни ввёл в настройках. Шапку не расширяем:
лишние права ломают ревю на GreasyFork (действующий инвариант).

Поэтому два режима:

| Сборка | Выбор и порядок из разрешённых | Добавление нового адреса |
| --- | --- | --- |
| Десктоп | да | да, любой |
| Юзерскрипт | да | нет, с подсказкой почему |

Две частности:

1. Адрес проверки обновлений зашит в `src-tauri/tauri.conf.json` на этапе
   сборки. Обновлениями занимается сама оболочка, до нашего кода это не
   доходит, из настроек меняться не может.
2. Домен плеера Kodik подставляется в кадр, а не в запрос, поэтому правка
   его домена имеет смысл только в десктопе.

### Закладка в итерации 5.1

Списки доменов сразу читаются через слой настроек, а не напрямую из
`core/constants.ts`. Константы становятся значением по умолчанию и основой
кнопки сброса. Тогда 5.4 — только интерфейс, без переделки логики.

## Инварианты, которые не нарушаются

- Сеть — только через `@/bridge`; к `graphql.anilist.co` — `credentials: 'omit'`.
- Каждый запрос берёт слот у `api/rate-limit.ts`, включая проверку сети.
- Никакого динамического `import()`; молчаливый `catch` запрещён.
- Новая настройка заводится в четырёх местах; тумблер видимости не
  отменяет монтирование.
- Вложенные `Ref` — через `shallowRef`; неиспользованный импорт роняет
  `vue-tsc`.
- Платформенный код выходит проверкой на первой строке либо разводится
  алиасом сборки.

## Чего не будет ни в одной итерации

Определения страны. Списка заблокированных адресов. Автоматического
включения чего-либо. Попыток обойти отказ. Своего туннеля и вшитых
серверов. Всплывающих окон: только строка в виджете и один закрываемый
тост.
