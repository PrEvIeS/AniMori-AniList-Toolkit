# AniMori 2.0.1 — журнал этапа 5

Версия: 2.0.1 (в разработке)
Ветка: `script&windows-dev`
Начат: 3 августа 2026

## Назначение папки

`docs/2.0.1/` — рабочие документы версии 2.0.1: журнал итераций, планы,
аудит. Документы версии 2.0.0 остаются в `docs/2.0.0/` и не правятся:
они описывают то, как всё было на момент релиза.

Общая карта проекта живёт уровнем выше — `docs/PROJECT-MAP.md`. Она не
привязана к версии и обновляется по мере изменения структуры.

## Правила ведения

1. Запись делается по требованию, а не после каждой правки.
2. Одна итерация — один раздел: что просили, что сделано, чем проверено,
   какие коммиты.
3. Причины важнее перечня строк: через месяц полезно знать, почему решение
   именно такое, а не какие файлы были затронуты.
4. Планы задним числом не правятся. Расхождение плана с фактом фиксируется
   отдельной строкой.
5. Порог одной части — 45–50 КБ. Дальше заводится следующая часть
   (`STAGE-5-PART-02.md` и так далее): полная перезапись большого файла
   через API рвётся на середине.

## Решения

### Р1. Блокировки сервисов в России (4 августа)

#### Проблема

Часть используемых источников в России недоступна или ограничена. При этом
приложение ведёт себя невнятно: виджеты не строятся, ошибки видны только в
логгере, пользователь не понимает, что дело в сети, а не в приложении.

#### Что рассматривалось

1. Предупреждать пользователя о необходимости VPN.
2. Дать возможность проксировать трафик самим.

Возражение владельца по второму пункту: стратегии обхода блокировок
устаревают едва ли не ежедневно, долгосрочного решения без постоянной
поддержки не выйдет.

#### Принятое решение

В гонке вооружений не участвуем. Приложение **не обходит** блокировки и
никогда не будет содержать ни своего туннеля, ни вшитых серверов, ни
списков, требующих сопровождения. Вместо этого две вещи, которые не
устаревают:

1. **Явная диагностика.** Приложение показывает, какой источник недоступен,
   и прямо предлагает включить VPN. Не зависит от того, чем и как
   блокируют, поддержки не требует.
2. **Поддержка чужой трубы.** Приложение умеет ходить через прокси, который
   пользователь поднял сам. Способ подключения к прокси стандартный и его
   никто не блокирует: блокируют конечные сервисы, а не сам протокол.
   Ломаться будет труба пользователя, а не наш код.

#### Ограничения по сборкам

**Юзерскрипт.** Проксировать нельзя в принципе: запросы идут через сеть
браузера, `GM_xmlhttpRequest` тоже. Доступна только диагностика и
предупреждение.

**Десктоп.** Два независимых канала трафика, путать их нельзя:

| Канал | Что идёт | Чем управляется |
| --- | --- | --- |
| WebView2 | сайт `anilist.co`, изображения, iframe плеера Kodik | только аргументами запуска до создания окна |
| Rust / `reqwest` | AniList GraphQL, Shikimori, anime365, AnimeThemes, словарь, проверка обновлений | настройками приложения на ходу |

#### Замеры 4 августа (Москва, бытовой провайдер)

Снято вручную через `node -e` с браузерным User-Agent, дважды: без VPN и с VPN.
Снимок нужен только для понимания состояний и начального значения поля
исключений. В логику кода он не попадает (см. принцип ниже).

| Хост | Без VPN | С VPN |
| --- | --- | --- |
| `graphql.anilist.co` | 404 — норма, принимает только POST | 404 |
| `anilist.co` | 200 | 200 |
| `s4.anilist.co` (картинки) | 200, 814 мс | 200, 1004 мс |
| `shikimori.io` | 200, 37 мс | 200 |
| `shikimori.rip` (резерв) | таймаут 10.7 с | 200 |
| `smotret-anime.online` | 200 | 200 |
| `anime365.ru` (резерв) | таймаут 10.7 с | таймаут 10.4 с |
| `api.animethemes.moe` | 403 Cloudflare | 200, 7768 мс |
| `v.animethemes.moe` (видео) | таймаут 10.7 с | 404 на корне — норма |
| `kodik-api.com` | 200 | 200 |
| `kodikplayer.com` | 200, 65 мс | 200 |
| `raw.githubusercontent.com` (словарь) | 200 | 200 |
| `api.github.com` | 200, остаток лимита 58/60 | 403, остаток 0/60 |
| `github.com` (файл обновления) | 200 | 200 |

Выводы из снимка:

1. **AnimeThemes недоступен целиком.** API отдаёт 403 даже с браузерным
   User-Agent, видеохост не отвечает вовсе. Виджет музыки без туннеля не
   работает. Заодно выяснилось, что без User-Agent Cloudflare отказывает всегда.
2. **VPN не только помогает, но и ломает.** Адрес выхода общий, лимит GitHub
   считается по адресу и был выбран чужими руками: остаток 0 против 58 без
   туннеля. Проверка обновлений через прокси будет падать там, где без него
   работает. Плюс время ответа растёт в разы.
3. **Цена мёртвого резерва — десять секунд ожидания.** Надо убедиться, что
   `MIRROR_TIMEOUT_MS` (5000) реально применяется во всех клиентах с зеркалами.
4. Зеркало `shikimori.rip` заведено в `core/constants.ts` с пометкой «фоллбэк для
   удалённых по РКН», то есть для российских пользователей, и именно из России
   недоступно. Назначению не соответствует.
5. MyAnimeList как сетевой источник не используется вообще: `idMal` нужен только
   как число для ключей кэша и поиска на Shikimori (отсюда имя хранилища
   `malCache`). Блокировка MAL на работу не влияет.

#### Поправки владельца по замерам

1. `anime365.ru` жив: при переходе в браузере сначала `ERR_TIMED_OUT`, затем
   редирект на `/users/login`. Из списка резервных не убираем. Вывод про
   короткий предел ожидания остаётся: домен, отвечающий не с первой попытки,
   не должен блокировать цепочку на десять секунд.
2. Главное: доступность сегодня ничего не говорит о доступности через неделю.
   Зашивать выводы из снимка в код нельзя.

#### Принцип: никаких зашитых выводов

В коде не должно быть ни одного решения, зависящего от того, что доступно
сегодня. Конкретно:

- Ни один хост не помечен в коде как заблокированный — ни AnimeThemes, ни
  какой-либо ещё. Никаких текстов вида «заблокировано в вашей стране».
- Предупреждение выдаётся по факту отказа в момент работы, а не по списку.
  Отвалится завтра Kodik — механизм сработает на нём без обновления
  приложения; разблокируют AnimeThemes — предупреждение само перестанет
  появляться.
- Списки резервных доменов остаются полными. Порядок выбирается по факту:
  домен, который ответил, запоминается на сеанс и опрашивается первым.
  Мёртвый на данный момент домен не удаляется, а уходит в конец очереди.
- Список исключений прокси — значение поля по умолчанию, которое пользователь
  правит руками, а не константа в коде.
- Проверка сети не имеет заранее известного правильного ответа. Она показывает
  три состояния: ответ есть; ответа нет вовсе; ответ есть, но не пускают.

Следствие для условия показа: решает **вид сбоя**, а не имя хоста и не код
ответа сам по себе. Сетевой отказ или таймаут (`BridgeHttpError` вида `network`
или `timeout`) — повод говорить про VPN. Код 403 — отдельный текст: связь есть,
но сервис не пускает. Код 404 не учитывается вообще.

#### План работ

**Часть 1 — диагностика и предупреждение (обе сборки).**

- Раздел «Сеть» в настройках с кнопкой проверки. Каждый источник опрашивается
  тем же способом, каким его дёргает приложение (AniList — POST), иначе
  проверка врёт.
- Предупреждение показывается **пользователю явно, в интерфейсе**, а не
  прячется в логгере (требование владельца). Показ однократный за сеанс, с
  возможностью закрыть.
- Предупреждение привязано к источнику: если молчит одна возможность, текст
  появляется в её виджете; если сыпется всё сразу — общая плашка.
- Источник сигнала — вид сбоя от моста, плюс существующий `net-probe`.

**Часть 2 — настройка прокси (только десктоп).** Начинается сразу после
части 1, отложена не была.

- Настройки: тип (HTTP / SOCKS5), адрес, порт, логин, пароль, список
  исключений (редактируемый).
- Для Rust-канала — свой транспорт на `reqwest` с `Proxy::all` вместо
  плагина `http`; поведение таймаутов и `credentials` сохранить без
  изменений, к `graphql.anilist.co` по-прежнему `omit`.
- Для WebView2 — аргументы запуска `--proxy-server` и
  `--proxy-bypass-list`. Задаются до создания окна, поэтому смена
  настройки требует перезапуска приложения (механизм уже есть).
- Раздельная маршрутизация обязательна: видео через чужой канал тормозит,
  а `api.github.com` через общий адрес получает отказ по лимиту (замер
  выше). Начальное содержимое исключений — именно значение по умолчанию.
- Пароль прокси лежит в файле настроек в открытом виде, как и токен
  AniList. Это должно быть честно написано в подсказке к полю.

**Часть 3 — опционально.** DoH для Rust-канала, если выяснится, что мешает
именно разрешение имён. На WebView2 не влияет.

**Попутно (выявлено замерами).** Проверить и при необходимости ввести
короткий предел ожидания на попытку к резервному домену и запоминание
рабочего домена на сеанс.

#### Что осознанно не делаем

- Свой туннель или вшитый клиент любого протокола: лишние мегабайты в
  установщике, ложные срабатывания антивирусов на NSIS-сборку и обязанность
  поддерживать чужие бинарники.
- Любые ухищрения, которые надо подкручивать после каждого шага
  регулятора.
- Определение страны пользователя и любые решения на его основе.

#### Замечание

Чаще всего VPN у пользователя включён на всю систему, и тогда всё работает
без нашего участия. Настройка прокси нужна тем, кто не хочет гнать через
туннель весь трафик, включая видео.
