# Стиль кода

## Комментарии — ОЧЕНЬ ЛАКОНИЧНЫ

Главное правило проекта. Читать до начала любой правки.

### Лимиты

| Место | Потолок |
| --- | --- |
| Шапка файла | 5 строк |
| Док-комментарий функции | 3 строки |
| Комментарий внутри кода | 1 строка |

Нужно больше — значит, объяснение идёт в `docs/`, а в коде остаётся ссылка на пункт.

### Что комментируем

Только неочевидное «почему»: ограничение платформы, обход дефекта, причина странного
порядка вызовов, цена решения.

### Что не комментируем

- Пересказ кода словами.
- Историю решений и отвергнутые варианты — им место в журнале этапа.
- Рассуждения, аргументы, самооправдания.
- Повтор того, что уже сказано в шапке файла.

### Зачем

К 5.3.7 комментарии заняли около 40% веса исходников. Следствия:

1. Файлы упёрлись в порог 25 КБ, после которого перезапись через API рвёт текст
   на середине (случай `proxy.rs`, коммит `e5e109a`).
2. Логику приходится дробить по файлам не по смыслу, а по весу.
3. Файл перестают читать целиком, и правки идут вслепую.

### Долг

Сплошная чистка комментариев по всем файлам запланирована отдельной задачей —
см. `docs/2.0.1/STAGE-5-PART-06.md`.
