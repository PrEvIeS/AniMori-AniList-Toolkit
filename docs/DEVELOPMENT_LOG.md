# Журнал разработки — AniMori Desktop

> Ветка: `desktop-dev`
> Базовая проверенная ревизия: `0540aef`
> Канонический источник поведения: монолит `animori.user.js` v1.9.1 (4658 строк)

## Назначение

Цель Этапа 1 — разобрать монолитный юзерскрипт на модули TypeScript с нулевой регрессией
поведения. Никакого Vue, Tauri и Bridge на этом этапе нет — только разборка.

Правила ведения журнала: пишем решения и причины, а не пересказ диффа. Строки монолита
указаны приблизительно. Обновляется по требованию, а не после каждого коммита.

История до `cf8a431` велась подробно, поблочно (20 разделов, 51 КБ). Та версия целиком
сохранена в истории git и доступна командой `git show cf8a431:docs/DEVELOPMENT_LOG.md`.
Здесь оставлено то, что нужно для продолжения работы: решения, отступления от монолита,
дефекты, риски и состояние этапа.

## 1. Каркас сборки

Vite 5.4.21 + `vite-plugin-monkey`, вход `src/main.ts`, вывод `dist/animori.user.js`
и `dist/animori.meta.js`. `minify: false`, `target: esnext`, alias `@` → `./src`,
`scss.api: 'modern-compiler'`, `define.__ANIMORI_PLATFORM__`.

Метаданные юзерскрипта перенесены 1:1: version `1.9.1`, `@match` только AniList и
`shikimori.io`, `@grant` из шести разрешений, `@connect` без добавлений. Лишние разрешения
не добавлять: любое расширение `@grant` или `@connect` — повод для перепроверки
модераторами Greasy Fork.

Стиль кода: Prettier без точек с запятой, одинарные кавычки, `printWidth: 100`.
Каждая итерация закрывается прогоном `npx tsc --noEmit` и `npx vite build` на стороне
разработчика; без успешной сборки итерация не считается закрытой.

## 2. Структура кодовой базы

```
src/core/      accent, constants, custom-links, db, dictionary, lifecycle, settings, types
src/api/       anilist, anime365, animethemes, dictionary, shikimori, shikimori-people, titles
src/utils/     dom, logger, name-match
src/features/  exporter, scanner, translator, media, search, ui
```

Ключевые решения ядра:

- **Настройки** — единый объект `settings` с `loadSettings()`/`saveSetting()`. Все `GM_getValue`
  собраны в одном модуле: на Этапе 3 чтение станет асинхронным (РИСК №1), и править
  придётся только его. `loadSettings()` вызывается первым шагом `bootstrap()`.
- **Логгер** — ядро (`utils/logger.ts`) не знает о своём UI: представление подключается
  через `registerLogSink()`. На Этапе 2 UI заменится на `LoggerModal.vue`, ядро останется.
- **IndexedDB** — `DB_MIGRATIONS` с идемпотентными шагами вместо цепочки `if (oldVersion < N)`.
  Версии 1..5 консолидированы в шаг 5. Модуль переезжает на Tauri без изменений.
- **Словарь** — три слоя (локальный, удалённый, пользовательский) собираются
  `rebuildDictionary()`; приоритет у пользовательского. Перескан перевода после правки
  словаря — через `registerRetranslateCallback()`, чтобы словарь не зависел от переводчика.
- **Акценты** — `AM_ACCENTS` с пресетами `site`/`sakura`/`mono`/`catppuccin`, применение только
  внутри `.am-accent-scope`, чтобы не красить интерфейс сайта.
- **Панель действий** — `registerActionButton()` + `ACTION_ORDER`, порядок кнопок задаётся
  данными, а не порядком вызовов.
- **Медиа-страница** — `registerMediaWidget()` и единый `MediaContext`. Виджеты не знают
  друг о друге; данные AniList и Shikimori грузятся один раз на тайтл.
- **Вставка HTML** — только через тег `html` с автоэкранированием и явным `rawHTML()`
  там, где разметка доверенная.

## 3. Асинхронные API

- **AniList** — `anilistQuery()`, токен из `AL_TOKEN`, пауза по 429 через `pauseAniList()`.
- **Shikimori** — `fetchShiki()` с перебором зеркал `SHIKI_DOMAINS`; возвращает домен, с которого
  пришёл ответ, иначе фоллбэк-ссылки ведут на недоступное зеркало.
- **Anime365** — самоотключение после `ANIME365_FAIL_LIMIT` подряд сбоев, троттлинг 180 мс.
- **Переводчик** — три очереди (`MED2`, `CHR2`, `STF3`), пакеты 40 и 10, дебаунс 300 мс.
  Наблюдатель мутаций один на всё приложение; сторонние модули подписываются через
  `registerMutationHook()`. Защита от рекурсии — класс `am-notr` (РИСК №4).

### Итерация 4 — UI настроек, словаря и логгера

Коммиты `aaa7561` (`features/ui/logger-ui.ts`, 486 строк), `4aac544`
(`features/ui/settings.ts`, 981 строка), `cf8a431` (подключение в `bootstrap()`).

Оверлей логгера: семь фильтров, поиск, группировка однотипных записей, JSON-вьюер,
счётчик непрочитанных, дамп состояния, копирование и скачивание. Отличия от монолита:
поиск идёт также по пути и деталям записи (сериализация в `try/catch`, чтобы циклическая
структура не роняла рендер); текстовый дамп собран в одну функцию вместо двух
расходящихся копий; дамп состояния собирается только из публичных геттеров, из-за
чего из него ушло поле `currentMediaId` (приватное состояние медиа-модуля).

Панель настроек: восемь вкладок, 13 переключателей и 3 поля доменов описаны таблицами,
а не повторяющимися блоками кода; типы ключей выведены из `AniMoriSettings` через mapped type,
поэтому новая настройка без правки таблицы не соберётся.

Отступление: импорт словаря из файла вызывает `upsertUserDictEntry()` вместо приватного
`amRetranslate()` монолита; ручной `rebuildDictionary()` убран, так как `upsert` делает его сам.

Квирк, перенесённый осознанно: оверлей логгера не помечен `am-notr`, как и в 1.9.1.

### Итерация 5 — SPA-жизненный цикл

Коммиты `849f835` (`features/media/index.ts`), `83ad7cc` (`core/db.ts`), `c4302e8`
(`core/lifecycle.ts`), `16de863` (`main.ts`), `0540aef` (`features/search/index.ts`).

Закрыты четыре дыры, возникшие именно при разборке монолита:

1. **Перехват навигации отсутствовал вовсе.** Новый `core/lifecycle.ts` ставит обёртки над
   `history.pushState` и `history.replaceState`, слушает `popstate` и держит страховочный
   пулинг `location.href` каждые 800 мс. Модуль не знает ничего о виджетах и селекторах:
   он лишь сообщает о смене адреса. В монолите та же логика была вмешана в `init()`
   и сама чистила DOM по списку классов. Отличие в лучшую сторону: обработчик обёрнут
   в `try/catch` — мы подменили сайту History API, и непойманное исключение вылетело бы
   наружу прямо из вызова `pushState`, то есть наш баг ломал бы навигацию AniList.
2. **Сборщик мусора не вызывался.** `runGarbageCollector()` был перенесён, но его вызов
   потерялся: кэш Shikimori рос бесконечно, а `CACHE_TIME` в 90 дней ни на что не влиял.
   Восстановлен запуск через 15 с после старта.
3. **Кнопка плеера не гаслась при уходе со страницы.** `#ru-player-btn` живёт в общей
   панели действий, а не в разметке виджета, поэтому `cleanupSelectors` её не снимал и кнопка
   оставалась висеть на списках и в профиле. Оверлей `#ru-player-overlay` при этом
   удаляется целиком, поэтому отдельно обнулять `src` у iframe не требуется — здесь порт
   чище монолита, который оставлял оверлей в DOM навсегда.
4. **Счётчик тем всегда показывал 0.** Темы кэшируются под префиксом `THEMES2_`, а `getDbStats()`
   искал `THEMES_`. Дефект монолита, затрагивал только статистику, сам кэш работал.

Для связи жизненного цикла с медиа-модулем добавлен экспорт `refreshMediaPage()` — аналог
`injectMediaExtensions()` монолита. Наблюдателя мутаций для этого недостаточно: переход
между однотипными страницами может не менять разметку сайдбара вообще.

Квирк поиска (`0540aef`): монолит опознавал поле поиска сравнением placeholder со строкой
'Поиск в AniList', то есть с результатом работы своего же переводчика. При
`translateInterface: false` русский поиск молча не работал, и любая правка формулировки
в `dictionary.json` его бы сломала. Теперь поле опознаётся по смыслу placeholder'а:
упоминание AniList плюс глагол поиска на любом из двух языков. Проверка оставлена узкой
сознательно: ложное срабатывание показало бы выпадашку поверх чужого поля ввода.
Это первое сознательное расхождение с поведением 1.9.1, утверждённое разработчиком.

Регрессии самого порта, найденные и закрытые по ходу:

- самодельная кнопка сравнения с инлайн-стилями вместо общей панели действий;
- `amSetAccent()` не вызывался при старте: сохранённый пресет акцента игнорировался;
- `if (!needTranslator) return` стоял до `openDB()`, из-за чего при полностью выключенном
  переводе умирали все медиа-виджеты. **Сценарий в браузере ещё не проверен.**

## 7. Инструментальные решения и грабли

- **Абсолютные адреса собирать только конкатенацией.** Литерал схемы внутри шаблонной
  строки дважды сворачивался при передаче файла в репозиторий и приводил к битым ссылкам.
  После отправки файлы с URL перечитывать с ветки.
- **Журнал пишется компактно.** У API нет операции «дописать в файл»: любое обновление —
  передача всего файла целиком. При 51 КБ отправка рвалась и стоила десятков минут,
  поэтому журнал переписан в сжатом виде, а поблочная история оставлена в git.
- **Поиск по коду в API неработоспособен на этой ветке** — всегда отдаёт пустой результат.
  Работают только чтение конкретных файлов и grep по локальной копии монолита.
- **Файлы отправляются по одному, последовательно** — параллельная отправка даёт гонку по ref.
- **Пуш идёт прямо в `desktop-dev`** без feature-веток и PR; проверка сборки — локально
  на стороне разработчика после каждой итерации.

## 8. Риски

Из `AUDITION.md`, актуальны на Этапах 2-4:

1. Синхронный `GM_getValue` против асинхронного store в Tauri — всё чтение настроек
   уже изолировано в `core/settings.ts`.
2. Cookies Shikimori не видны Rust-клиенту — авторизованные запросы потребуют отдельного
   решения в Bridge.
3. React уничтожает вставленные узлы — виджеты обязаны быть идемпотентными.
4. Рекурсия мутаций переводчика — свою разметку помечать `am-notr`.
5. WebKitGTK без GStreamer не воспроизведёт H.264/AAC — касается плеера на Linux.
6. Логгер держит до 1000 записей на тип, а оверлей рендерит их без виртуализации —
   до шести тысяч узлов в DOM. Нужен кольцевой буфер 300-500 или виртуальный список
   при переводе на Vue.
