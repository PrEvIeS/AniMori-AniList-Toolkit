# Карта проекта, часть 2: модули

Продолжение `PROJECT-MAP.md`. Здесь — слой внешних сервисов, мост, ядро
и прикладные возможности.

---

## 4. Слои и правила зависимостей

```
features/  →  api/  →  bridge/
    ↓          ↓
  core/  ←─────┘
    ↓
  utils/
```

Правила:

- `core/` ничего не знает о `features/`. Нарушение этого даёт цикл импортов
  и падение на старте.
- Ни один модуль не обращается к `GM_*` или `@tauri-apps/*` напрямую — только
  через `@/bridge`.
- Сетевые вызовы живут только в `api/`. Виджет или модалка, стучащая в сеть
  напрямую, обходит ограничитель темпа и рано или поздно ловит 429.
- `utils/` не импортирует ничего, кроме типов.

## 5. Мост (`src/bridge/`)

`IBridge` — четыре группы возможностей:

| Группа      | Браузер                       | Десктоп                                     |
| ----------- | ----------------------------- | ------------------------------------------- |
| `storage`   | `GM_getValue` / `GM_setValue` | плагин store, файл `animori-settings.json`  |
| `http`      | `GM_xmlhttpRequest`           | плагин http (запрос идёт из Rust, без CORS) |
| `clipboard` | `GM_setClipboard`             | плагин clipboard-manager                    |
| `shell`     | `location.reload()`           | команда `animori_reload`                    |

Поле `platform` (`'userscript'` или `'tauri'`) есть, но использовать его для ветвления
логики не стоит: разница платформ должна уходить в реализацию моста или
в алиас сборки. Поле оставлено для диагностики и текстов в интерфейсе.

`HttpRequestOptions` требует явно указывать `credentials`. Для `graphql.anilist.co`
всегда `'omit'`: с куками сервис отвечает 403 через Cloudflare.
Ошибки сети приходят одним типом `BridgeHttpError` с видом `network`, `timeout`
или `abort`, чтобы вызывающий код не разбирал строки сообщений.

## 6. Слой API (`src/api/`)

### Ограничитель темпа (`rate-limit.ts`)

Один на весь проект, по экземпляру на источник. Два ограничения сразу:
минимальный интервал между запросами и потолок за окно в минуту. Любой запрос
берёт слот через `acquireSlot()`.

Ответ 429 обрабатывается не повтором в лоб: читается `Retry-After`, очередь
засыпает целиком. Для AniList при 403 и 429 действует отступ: 30 секунд,
дальше удвоение до потолка в 15 минут.

Заявленные лимиты: Shikimori — 5 запросов в секунду и 90 в минуту,
AniList — около 90 в минуту (фактически часто 30). Наши настройки взяты
с запасом от этих чисел.

### Источники

- `anilist.ts` — единственная точка GraphQL. Здесь же хранится токен пользователя
  и логика отступа.
- `shikimori.ts` — `fetchShiki` с перебором зеркал. Возвращает не только данные,
  но и сработавший домен: ссылки в интерфейсе строятся от того же зеркала,
  с которого пришли данные.
- `shikimori-people.ts` — самый капризный источник. Поиск имён идёт по схожести
  строк с порогом; при низкой уверенности включается гард тёзок: кандидат
  проверяется по общим тайтлам, иначе вместо одного Сато подставляется другой.
  После всплеска 429 модуль выдерживает паузу в шесть секунд.
- `anime365.ts` — русские названия и описания; только аниме. Счётчик ошибок
  гасит источник до конца сессии, если зеркала не отвечают.
- `titles.ts` — тонкий выборщик: берёт основной источник из настроек, при пустом
  ответе — запасной. Весь остальной код перевода тайтлов ходит только сюда.
- `animethemes.ts` — OP и ED для виджета музыки.
- `dictionary.ts` — загрузка `dictionary.json` с GitHub. Сначала отдаётся кэш,
  сеть идёт фоном и обновляет словарь через колбэк, чтобы перевод не ждал сети.

## 7. Ядро (`src/core/`)

### settings.ts

Интерфейс `AniMoriSettings` и `DEFAULT_SETTINGS` — единственный источник правды
о составе настроек. `readSettings()` читает все ключи одним `Promise.all`,
а не последовательно: в десктопе каждое чтение — IPC-вызов.

Объект `settings` существует в единственном экземпляре и правится на месте:
его импортируют десятки модулей, и подмена ссылки оставила бы их со старым
объектом.

Завести новую настройку — четыре места:

1. поле в `AniMoriSettings`;
2. значение в `DEFAULT_SETTINGS`;
3. чтение в `readSettings()` с ключом хранилища;
4. элемент в `features/ui/settings-state.ts` и `SettingsModal.vue`.

Пропуск любого пункта даёт настройку, которая либо не сохраняется, либо не
отображается. Миграции старых ключей живут там же, в `readSettings()`
(пример: старый `set_titles` развёрнут в пару «основной и запасной источник»).

### db.ts

IndexedDB с двумя основными хранилищами: `malCache` (ответы AniList по id)
и `shikiCache` (карточки Shikimori с меткой времени). Срок годности — 90 дней,
чистка отложена на 15 секунд после старта, чтобы не мешать первой отрисовке.

### lifecycle.ts, dictionary.ts, constants.ts

`lifecycle.ts` описан в части 1. `dictionary.ts` склеивает удалённый словарь
с личным: личный всегда перевешивает. `constants.ts` — домены, сроки кэша,
признаки текущего сайта и таблицы для правил перевода.

## 8. Прикладные модули (`src/features/`)

### translator/ — перевод

Два независимых механизма:

1. Интерфейс — словарь и правила (`rules.ts`), без сети. Сначала точное
   совпадение строки, потом шаблоны для динамики: даты, сезоны, «через N
   часов», строки активности. Русские числительные требуют трёх форм слова,
   поэтому в таблицах хранятся тройки, а не одно слово.
2. Названия и имена — сеть и кэш (`api/titles.ts`, `api/shikimori-people.ts`).
   Работа идёт очередями с батчами и ограничением попыток.

`registerMutationHook()` — единственный наблюдатель мутаций на весь проект.
Медиа-модуль подписывается на него, а не заводит второй.

### media/ — виджеты страницы тайтла

`index.ts` держит жизненный цикл: разбор адреса `/anime/<id>` или `/manga/<id>`,
загрузка контекста (AniList, через MAL id — Shikimori, всё с кэшем),
вызов виджетов. Каждый виджет — `{ name, cleanupSelectors, mount(ctx) }`.

Три неочевидных правила:

- виджет обязан сам проверять своё наличие: `mount` вызывается многократно,
  потому что React регулярно выкидывает чужие узлы;
- падение одного виджета не должно убирать остальные, поэтому каждый вызов
  обёрнут отдельно;
- после каждого ожидания сети проверяется, что пользователь всё ещё на том же
  тайтле. Переход, случившийся во время загрузки, не теряется: он
  запоминается и дожимается одним повтором по последнему адресу (дефект A4).

Кнопка плеера — исключение: она живёт в общей панели действий, а не в разметке
виджета, поэтому гасится отдельно при уходе со страницы тайтла. Узлом владеет
Vue, ручная правка стиля была бы стёрта при перерисовке.

Состав виджетов: плеер, рейтинги, дерево франшизы, музыка, внешние ссылки.
Порядок регистрации в `main.ts` задаёт порядок блоков в сайдбаре.

#### player.ts

Поиск в Kodik по MAL id, оверлей на весь экран, списки озвучек и серий,
подсветка просмотренного по прогрессу AniList, избранные озвучки в хранилище.
Серии переключаются без перезагрузки кадра через `postMessage`; собственный
выбор серий Kodik скрыт параметром встраивания. На выбор качества это
не влияет: выше 720p в каталоге почти ничего нет.

Запасной путь — `find-player` по shikimori id, если поиск ничего не вернул.

### scanner/ — сравнение списков

`compare.ts` сопоставляет списки Shikimori и AniList по MAL id и раскладывает
расхождения по категориям: нет в AniList, разные статусы, разные оценки,
разный прогресс. Есть список игнора: отмеченные строки больше не всплывают.
Результат сверки — вход для переноса: переносятся только расхождения,
а не весь список.

### exporter/ — перенос

Историческое название папки — экспортёр, фактически это импорт: чтение
списков Shikimori и запись в AniList. Токен AniList вводится вручную через
приложение в личном кабинете разработчика. Отказ авторизации распознаётся
отдельно от сетевых ошибок: повторять запрос с отвергнутым токеном бессмысленно.

Кнопка живёт в панели действий на AniList и скрывается тумблером. Скрытие —
только видимость: модуль всё равно инициализируется, иначе переключение
тумблера требовало бы перезагрузки.

### search/ — русский поиск

Поле поиска опознаётся по смыслу placeholder (упоминание AniList плюс глагол
поиска на любом из двух языков), а не по точному тексту: после перевода
текст другой. При вводе кириллицы (дебаунс 600 мс) идёт поиск на Shikimori
по четырём категориям, затем один GraphQL-запрос с алиасами переводит найденное
в сущности AniList. Результаты рисуются своими узлами поверх родной
выпадающей панели; родные узлы прячутся, а не удаляются.

`dict-capture.ts` попутно копит соответствия «русское название — id» в локальный
словарь, чтобы повторные запросы не ходили в сеть.

### adblock/ — блокировщик рекламы

Две реализации за одним алиасом `@adblock-impl`: десктопная и заглушка для
браузера (там за рекламу отвечает расширение пользователя). В интерфейсе —
один тумблер в разделе «Прочее», без подразделения на виды рекламы.

Десктопная часть работает в два уровня: косметика в DOM (чужие узлы прячутся,
а не удаляются — удаление ломает разметку React) и сетевая блокировка
в оболочке. `net-probe.ts` — разведка: собирает адреса из вложенных кадров,
чтобы было чем пополнять списки; модуль оставлен намеренно.

### ui/ — интерфейс надстройки

- Панель действий (`ActionPanel.vue`, `action-panel-state.ts`, `actions.ts`) — единое
  место для всех кнопок. Порядок задан числами, а не порядком регистрации:
  настройки, журнал, сравнение, перенос.
- Настройки (`SettingsModal.vue`, `settings-state.ts`) — самый крупный экран.
  Состояние вынесено из компонента отдельно, чтобы к нему могли обращаться
  другие модули.
- Журнал (`LoggerModal.vue`, `logger-state.ts`, `utils/logger.ts`) — кольцевой буфер
  записей с типами (INFO, WARN, ERROR, DB, API, QUEUE) и инспектором деталей.
  Молчаливо глотать исключения запрещено: любой `catch` либо лечит, либо пишет.
- Навигация (`NavPanel.vue`, `nav.ts`) и перезагрузка (`reload.ts`) — в браузере
  навигацию даёт сам браузер, в окне приложения её нет, поэтому кнопки
  рисуем сами.
- Ссылки (`links.ts`) — перехват кликов по внешним адресам и шаблоны своих
  ссылок с подстановками русского и латинского названия.

### Сеть и доступность (`core/net-health.ts`, `features/ui/net-check.ts`)

Учёт доступности ведётся по идентификаторам источника (`anilist:graphql`,
`shikimori:<домен>`, `anime365:<домен>`, `animethemes`, `dictionary`).
Источник считается проблемным после двух неудач подряд; отказ авторизации,
429 и отмена запроса не учитываются, а 404 считается успехом: сервис ответил.
Общая беда — два разных источника за минуту, тогда показывается тост.

Проверка из вкладки «Разработчик» идёт последовательно, а не веером:
одновременные пробы по зеркалам ловили 429 у Shikimori. Пробы дают вердикт
по каждому адресу и предлагают предпочтённое зеркало на сеанс.

### Прокси в интерфейсе (`core/proxy.ts`, `SettingsProxyCard.vue`)

Разбор и сборка настроек прокси живут в ядре и общие для обеих сборок,
но применяются только в десктопе: юзерскрипт проксировать нельзя, ему
доступна лишь диагностика. Карточка показывает исход применения из оболочки
и умеет пробовать адрес вручную; порт `0` означает «значения нет».
