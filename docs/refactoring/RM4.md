# Этап 4: Сборка Desktop-приложения (Интеграция Tauri 2.0)

Цель: Создание независимого кроссплатформенного исполняемого файла с внедренным
скриптом на базе единой кодовой базы, обход сетевых ограничений браузера и
обеспечение нативного UX. Стек: Tauri 2.0, Rust, WebView, Vite Environment
Modes.

## 4.1. Инициализация рабочей среды Tauri

- Действие: Выполнение команды tauri init в корне существующего Vite-проекта
  для генерации директории src-tauri (Rust-бэкенд).
- Конфигурация: Настройка базовых параметров окна и манифеста приложения в
  конфигурационном файле Tauri (tauri.conf.json).

## 4.2. Интеграция системных плагинов

- Действие: Установка и регистрация нативных плагинов Tauri для реализации
  контракта IBridge, разработанного на Этапе 3.
- Зависимости:
  - @tauri-apps/plugin-http (выполнение сетевых запросов на стороне ОС).
  - @tauri-apps/plugin-store (работа с файловой системой для хранения кэша и
    настроек).
  - @tauri-apps/plugin-clipboard-manager (доступ к системному буферу
    обмена).

## 4.3. Настройка инъекции скрипта (Rust Backend)

- Действие: Модификация точки входа бэкенда (src-tauri/src/main.rs).
- Логика:
  - Использование макроса include_str! для включения собранного Vite
    JS-бандла (animori.build.js) в тело исполняемого файла на этапе
    компиляции (compile-time).
  - Конфигурация WindowBuilder на запуск внешнего URL (https://anilist.co).
  - Передача встроенного JS-кода в метод .initialization_script(), что
    гарантирует выполнение скрипта в контексте WebView до завершения
    загрузки DOM целевого сайта.

## 4.4. Конфигурация политик безопасности (Capabilities)

- Действие: Настройка разрешений (Permissions) для плагинов в файле
  src-tauri/capabilities/default.json.
- Устранение CORS: Явное добавление масок целевых доменов
  (graphql.anilist.co/*, shikimori.io/*, kodik-api.com/*, anime365.ru/*) в
  allowlist плагина HTTP. Это легитимизирует запросы бэкенда и позволяет
  WebView получать данные с любых источников без браузерных блокировок.

## 4.5. Desktop UX и Системная интеграция

- Действие: Настройка нативного пользовательского опыта и связи с операционной
  системой.
- Маршрутизация внешних ссылок: Интеграция @tauri-apps/plugin-shell. Настройка
  правил навигации: внутри WebView разрешен переход только по доменам
  anilist.co. Клики по любым внешним ресурсам (Shikimori, RuTracker, плееры и
  др.) перехватываются на уровне Rust-бэкенда и передаются системному процессу
  для открытия в браузере пользователя по умолчанию.
- Персистентность окна: Подключение @tauri-apps/plugin-window-state.
  Обеспечение автоматического сохранения и восстановления геометрии окна
  (размер, позиция на мониторе, состояние максимизации) между запусками
  программы.
- Управление навигацией (SPA): Интеграция слушателей глобальных событий
  (глобальные шорткаты и боковые аппаратные кнопки мыши Back/Forward) с их
  трансляцией в методы history.back() / history.forward() внутри WebView,
  чтобы обеспечить привычную браузерную навигацию внутри приложения.

## 4.6. Оркестрация процесса сборки

- Действие: Настройка единого пайплайна CI/CD и скриптов в package.json.
- Мультитаргетинг: Разделение команд запуска с использованием переменных
  окружения Vite (например, --mode userscript и --mode tauri). Это
  гарантирует, что модуль моста (src/bridge/index.ts) подтянет корректную
  реализацию API в зависимости от типа собираемого релиза.

## 4.7. Настройка перехвата всплывающих окон (Popup Interceptor)

- Интеграция обработчика on_new_window в Rust-бэкенде.
- Логика: если опция блокировки из пункта 2.8 включена, попытки iframe плеера открыть стороннее окно пресекаются. Если опция выключена, новые окна передаются в плагин shell и открываются в системном браузере пользователя.

## 4.8. Модификация CSP-заголовков (on_web_resource_request)

- Реализация перехватчика сетевых ответов от anilist.co на стороне Rust.
- Ослабление/удаление оригинальных заголовков Content-Security-Policy (в частности frame-src и connect-src), что позволяет WebView беспрепятственно загружать фреймы Kodik и делать сторонние запросы.

## 4.9. Система автообновлений (Tauri Auto-Updater)

- Конфигурация нативного плагина обновлений Tauri.
- При запуске приложения Rust-бэкенд опрашивает API GitHub Releases вашего репозитория. При наличии новой версии пользователю предлагается бесшовное автообновление бинарного файла (.exe / .dmg).

## 4.10. Автоматизация сборки (GitHub Actions CI/CD)

- Настройка единого workflow-файла .github/workflows/release.yml.
- При пуше тега с версией GitHub Actions автоматически собирает два таргета:
  - animori.user.js (для публикации на GreasyFork).
  - Нативные инсталляторы AniMori_Setup.exe (Windows), .dmg (macOS) и .AppImage (Linux), которые автоматически прикрепляются к GitHub Release (и используются плагином Auto-Updater).

Итог Этапа 4: На выходе формируются нативные инсталляторы (.exe, .dmg,
.AppImage). Приложение работает автономно от браузера, корректно интегрируется в
ОС (открытие ссылок, управление окном), не подвержено внешним блокировкам сети и
делит 100% бизнес-логики с версией для браузерного расширения.
