# src

## Purpose

Общая кодовая база юзерскрипта и десктопного приложения: TypeScript, Vue 3 SFC и один общий SCSS. Ровно один вход — `main.ts`, — из которого Vite собирает оба таргета. Различий по платформе внутри прикладного кода нет: они спрятаны за `bridge/` и разведены алиасами на этапе сборки.

## Key Files

| File | Description |
|------|-------------|
| `main.ts` | Точка входа обеих сборок. Гейт готовности DOM, `bootstrap()` со строгим порядком шагов, привязка подсистем к SPA-навигации (`wireLifecycle`), сторож живости страницы для прокси |
| `style.scss` | Всё оформление проекта одним файлом (~1960 строк). Классы `am-*`, `amk-*`, `animori-*`; на них ссылаются SFC, у которых стили почти всегда **не** scoped |
| `vite-env.d.ts` | Объявления `__ANIMORI_PLATFORM__`, `__ANIMORI_VERSION__` и полного GM-API (`GM_xmlhttpRequest`, `GM_getValue`, …), которого нет в `@types/greasemonkey` |

## Subdirectories

| Directory | Purpose |
|-----------|---------|
| `bridge/` | Контракт платформы `IBridge` и две его реализации (см. `bridge/AGENTS.md`) |
| `core/` | Ядро: настройки, константы, IndexedDB, словарь, жизненный цикл SPA, здоровье сети, типы (см. `core/AGENTS.md`) |
| `api/` | Клиенты внешних API с зеркалами, ограничением темпа и бэкоффом (см. `api/AGENTS.md`) |
| `features/` | Прикладные модули: переводчик, медиа-виджеты, поиск, сканер, экспорт, UI, адблок (см. `features/AGENTS.md`) |
| `utils/` | Платформонезависимые утилиты: журнал, DOM, матчер имён, монтировщик Vue (см. `utils/AGENTS.md`) |

## For AI Agents

### Working In This Directory

- **Порядок шагов в `bootstrap()` значим и выведен опытом.** Каждый шаг обёрнут в `step()`, чтобы падение одного не унесло остальные. Всё, что читает `settings`, идёт строго после `loadSettings()`. Адблок — раньше любого UI (иначе баннер мигнёт). `wireLifecycle()` — после `initMedia()`. Не переставляй шаги без причины и опиши причину комментарием.
- **Направление импортов:** `utils` → `core` → `api` → `features` → `main.ts`. Обратная стрелка — цикл. Ядро не знает о `features`: именно поэтому привязка задач роута живёт в `main.ts`, а не в `core/lifecycle.ts`.
- **Алиасы.** `@/...` → `src/...`. `@bridge-impl` и `@adblock-impl` — псевдопути, цель которых выбирает `resolve.alias` по `mode`. Ключи в `vite.config.ts` обязаны идти **до** `@`: строковые алиасы сопоставляются по порядку.
- **`main.ts` не должен знать о платформе.** Отсюда заглушки `impl.noop.ts` вместо `if (isTauri)`.

### Testing Requirements

`npm run typecheck` перед любым коммитом. Дальше — сборка нужного таргета и ручной прогон на живом `anilist.co`; автотестов нет.

### Common Patterns

- **Логирование через `Logger(type, message, details)`** из `utils/logger`. Типы: `INFO`, `WARN`, `ERROR`, `DB`, `API`, `QUEUE`. Записи видны во встроенном логгере.
- **Класс-иммунитет `am-notr`.** Всё, что переводчик не должен трогать (наша собственная разметка), помечается им. Без этого Vue и переводчик зацикливаются на взаимных мутациях.
- **`*-state.ts` рядом с точкой монтирования.** Реактивное состояние выносится отдельно от модуля, который монтирует SFC, иначе получается цикл «модуль → SFC → модуль».
- **SCSS общий, не scoped.** Переименование класса в SFC без правки `style.scss` тихо ломает вид.

## Dependencies

### Internal

Замкнута сама на себя; наружу выходит только через `bridge/` (к GM-API или к Tauri) и через `dist/` для `src-tauri`.

### External

`vue`, `@tauri-apps/*` (только внутри `bridge/TauriBridge.ts` и `TauriProxyDiagnostics.ts`), GM-API (только внутри `bridge/MonkeyBridge.ts`).
