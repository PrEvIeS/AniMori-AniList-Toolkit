# search

## Purpose

Две функции, объединённые работой с поиском и текстом на странице: русский поиск в шапке AniList (аниме, манга, персонажи, персонал) и контекстный захват выделенного текста в локальный словарь.

## Key Files

| File | Description |
|------|-------------|
| `index.ts` | Русский поиск: перехват ввода в родной выпадашке AniList, запрос к Shikimori, маппинг MAL id → тайтлы AniList, отрисовка результатов. `initSearch()` поднимает и захват словаря |
| `dict-capture.ts` | Выделение латиницы на странице → всплывающая кнопка «Перевести» → мини-форма → запись в локальный словарь и применение вживую |

## For AI Agents

### Working In This Directory

- **Схема обхода:** AniList не ищет по русским названиям. (1) Кириллица в поле → ищем на Shikimori; (2) полученные MAL id одним GraphQL-запросом маппим в тайтлы AniList; (3) рисуем результаты в родной выпадашке сайта, подстраиваясь под его разметку. Шаг 3 — самое хрупкое место: он зависит от вёрстки AniList.
- **Корневые поля `Character` и `Staff` в AniList отдают 404 на пустой результат.** Поэтому каждый персонаж запрашивается через алиас `Page(perPage: 1)` — так приходит пустой список вместо ошибки. Не «упрощай» обратно.
- **Эндпоинты `/search` у Shikimori игнорируют `&limit`** — списки режутся на клиенте.
- **Класс `am-notr` на форме захвата обязателен:** иначе переводчик начнёт переводить собственную форму и породит рекурсию мутаций.
- **Логика словаря живёт не здесь.** `upsertUserDictEntry()` из `core/dictionary.ts` сам пересобирает словарь и дёргает ре-скан DOM; в `dict-capture.ts` только императивный UI (без Vue — это единственный UI-модуль проекта, собранный на `html\`\`` из `utils/dom`).

### Testing Requirements

Поиск: ввести кириллицу в поле поиска AniList — результаты должны появиться в родной выпадашке; проверить все четыре типа (аниме, манга, персонаж, персонал) и пустой результат. Захват: выделить латиницу на странице, добавить перевод, убедиться, что он применился **без перезагрузки**.

### Common Patterns

- Слушатели вешаются на `body`, готовой разметки сайта модуль не требует — поэтому шаг «поиск» в `bootstrap()` может идти рано.
- Результаты Shikimori фильтруются по `scoreNameMatch` с порогом 80 (поиск по всему каталогу).
